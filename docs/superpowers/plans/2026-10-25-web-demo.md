# Web Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A demo page on GitHub Pages where anyone can convert a video on a vd-oprezer server, with an expert log, plus the opt-in CORS the server needs for it.

**Architecture:** The server gets an opt-in CORS hook (`corsOrigins` / `CORS_ORIGINS`). `web/` is its own npm package (vanilla TypeScript + Vite, no runtime deps). The UI knows only a backend contract (`web/src/backend.ts`). One adapter maps it to vd-oprezer's HTTP API. A pure state module (`app.ts`) drives an in-place DOM view, and a separate workflow builds and deploys to Pages.

**Tech Stack:** Fastify 5 (server, existing); Vite + TypeScript 6 + tsx + `node:test` (web); GitHub Actions + `actions/upload-pages-artifact` / `actions/deploy-pages`.

**Spec:** `docs/DECISIONS.md`, section **11. Web demo** (11a, 11b, 11c). Read it first; this plan doesn't repeat its reasoning.

## Global Constraints

- `web/` imports nothing from `src/` or the repo root. It has **no runtime dependencies**, only devDependencies: `vite`, `typescript` (`^6`, same major as root), `tsx`, `@types/node`.
- Server change: **no new npm dependency** (own hook, not `@fastify/cors`).
- ESM, Node 24. Relative imports use `.js` extensions. Builtins use the `node:` prefix.
- TypeScript in `web/` uses the same strictness as root: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `verbatimModuleSyntax`, `isolatedModules`.
- Tests sit next to the code (`web/src/app.test.ts`), run with `node:test` via tsx.
- Done = root `npm run check` **and** `npm run check` in `web/` both pass.
- **Don't commit unless Esteban asks** (CLAUDE.md). The "Check" step ends each task in place of a commit.
- Esteban works on Windows PowerShell: npm scripts must not use `VAR=x cmd` syntax. Give manual commands in both forms.
- Every `localStorage` access is wrapped in try/catch, and the page works without storage.
- Visitor copy is exactly the table in spec 11b. Raw error codes appear in the expert log only.
- Vite `base: "./"`.
- Only `main.ts` reads `import.meta.env`, `localStorage` and creates object URLs. `app.ts` and adapters stay free of those.

## Review Focus

1. **Output bigger than input** (likely with the `youtube` preset, CRF 18): the summary must say "12% larger", never "-12% smaller". Test in Task 2.
2. **Cancel before the upload finishes**: there's no job id yet, so the adapter must abort the XHR and send **no** `DELETE /jobs/undefined`. Test in Task 3.
3. **Backend URL with a trailing slash or a path prefix** (`https://host/api/`): requests go to `https://host/api/presets`. A URL typed without a scheme (`localhost:3000`) is rejected rather than stored. Tests in Tasks 2 and 3.
4. **A reverse proxy in front of the demo server** (needed for https) answers 502/504 with an HTML body when Node is down. The adapter must not crash parsing JSON, and it maps those statuses to `unreachable`. Test in Task 3.
5. **Changing file, preset or backend URL while a conversion runs** is ignored, not half-applied. Test in Task 2. The view also disables those inputs (Task 4).

describe("CORS", () => {
  const origin = "https://demo.example";
  const acao = (res: Response) => res.headers.get("access-control-allow-origin");

  it("adds Access-Control-Allow-Origin for listed origins only", async () => {
    await start({ corsOrigins: [origin] });

    assert.equal(acao(ok), origin);
    assert.match(ok.headers.get("vary") ?? "", /origin/i);
    assert.equal(acao(await fetch(`${base}/presets`, { headers: { origin: "https://other.example" } })), null);
  });

  it("allows any origin with '*'", async () => {
    await start({ corsOrigins: ["*"] });
    assert.equal(acao(await fetch(`${base}/presets`, { headers: { origin } })), "*");
  });

  it("sends no CORS headers and has no OPTIONS routes by default", async () => {
    await start();
    assert.equal(acao(await fetch(`${base}/presets`, { headers: { origin } })), null);

      assert.equal(acao(res), origin);
      assert.equal(res.headers.get("access-control-allow-methods"), "GET, POST, DELETE");
      assert.equal(res.headers.get("access-control-max-age"), "86400");

**Interfaces:**
- Consumes: `backend.ts` (Task 2).
- Produces: `export const createBackend: CreateBackend`. Export `kindFor(status: number, code?: string): ErrorKind` too (tested directly).
- Browser APIs it uses (the fakes implement exactly these):
  - `XMLHttpRequest`: `open`, `send`, `abort`, `status`, `responseText`, `onload`, `onerror`, `onabort`, `upload.onprogress`
  - `EventSource`: constructor, `addEventListener("job" | "deleted" | "open" | "error")`, `readyState`, `close`, static `CONNECTING = 0`, `CLOSED = 2`
  - `fetch` with `Response.body` streaming

Behaviour (spec 11b, "vd-oprezer adapter"):

- URLs are `baseUrl.replace(/\/+$/, "") + path`, never `new URL(path, base)`, so a path prefix survives.
- `kindFor` maps:

  | Status / code | Kind |
  |---|---|
  | 413 | `too_large` |
  | 503 + `QUEUE_FULL` | `busy` |
  | 422 | `unsupported` |
  | 400 | `rejected` |
  | 404 | `expired` |
  | 0, 502, 504 | `unreachable` |
  | anything else | `failed` |

  A job `error.code === "INVALID_ARGUMENT"` maps to `rejected`. Any other job error maps to `failed`.
- Error bodies: parse JSON in try/catch. Use `body.message` when present, otherwise `"HTTP <status>"`.
- Log entries, labels without the base URL:
  - `GET /presets`, `POST /jobs`, `GET /jobs/<id>/output`, `DELETE /jobs/<id>`, each with `status`, `ms` and `data` (the parsed JSON, or `{ bytes }` for the output)
  - `job <status>`, plus ` <n>%` while running, with the Job as `data`
  - `stream reconnecting` and `stream lost`
- After a successful download: a best-effort `DELETE` (with `keepalive: true`, errors swallowed).

  file(file: File): void;
  preset(id: string): void;
  convert(): void;
  cancel(): void;
  tryAgain(): void;
  another(): void;
  expert(): void;

/** Binds handlers once and returns render(state), which updates the static markup in place. */

Rules the implementer can't infer:
- **Static markup lives in `index.html`** (spec 11b screen, layout B). `render` only changes text, `hidden`, `disabled`, `value`, `<progress>.value` and attributes. It never replaces nodes, so focus, the file input and video playback survive updates. Exceptions:
  - preset radios are rebuilt only when `state.presets` changes identity
  - log lines are appended, not re-rendered (track how many are shown)
- **Log lines** are `<details><summary>HH:MM:SS label status · ms</summary><pre>JSON</pre></details>`, so clicking expands with no JS.
- **Video:** set `src` only when the done URL changes. Its `loadedmetadata` calls `handlers.videoInfo`. **Download** is an `<a download>` whose `href` is the done URL and whose `download` is the filename.
- **Presets `{ error }`:** the flow shows "Can't reach the demo server." in place of the cards. The reason is already in the log.
